# clawd 工作流（水彩 + 墨线，自由场景）

> studio 的提示词直接引用本文件的各节（按 `## ` 标题切分），改这里就是改提示词。
> 画组件的规则不在这里，在 `docs/API.clawd.md`（脚本生成）。

## 原则

- **统一画风，不统一内容**。画风是固定的：水彩铺色 + 手绘墨线、纸纹、线条抖动，由引擎和组件保证，你不需要、也不应该去设计新的画风。世界、隐喻、场景、道具按本期主题单独设计，不要照搬示例或上一期的东西。
- **先复用，再新建**。库里有"确实就是这个东西"的组件就用；没有，或者用了会"不像"，就在 `newComponents` 里声明新组件，由画组件阶段现画。宁可新建，也不要拿不相干的组件凑数（用蝴蝶代表病毒、用荷叶代表细胞都是错的）。
- **一个故事，固定的演员**。全片只有两种"人"：讲解的豆丁，和演故事的角色。
  - 故事角色：一个主角，最多再加一个配角。每个角色从头到尾只用一个组件，长得一样，不换样子，也不换别的角色顶替。
  - 主角在旁白讲到 ta 的时候出场；配角只在旁白明确讲到 ta 时才当主体。连续的故事镜头沿用同一个主体，只有旁白换了讲述对象才换。讲机制、环境、物件的镜头，主体可以是道具或前景，画面里不必有角色。
  - 豆丁只负责"讲"：开头引入、中段点题、结尾收束时出场，其余镜头不出现；主角自己讲（`host: protagonist`）时豆丁完全不出场。
  - 比喻里的东西（一个"账本"、一个"闹钟"）做成**没有脸的道具**：机器、工具、器物，不要做成人形或带脸的化身。会表情的只有 cast 里的角色。
- **主角要有脸、有状态**。流动或变形的主体（红细胞、水滴、包裹、电子……）做成有表情的角色，状态从外观就看得出来（颜色、表情、身边带着的东西）。
- **颜色语言**。整期固定几种颜色的含义（如：蓝 = 氧气，灰 = 二氧化碳；暖红 = 动脉，紫蓝 = 静脉），全片保持一致。
- **画面承载旁白**。每一句旁白，观众都应该"看见"它在说什么发生了变化；只有字幕、只有镜头推拉不算。

## Stage 0 · 选题适配

逐条判断，前三条必须都满足：

1. 能拆成 3–6 个步骤或部件。
2. 有东西在步骤之间流动、变形或传递（可以做成主角）。
3. 结论能"演"出来：变形、对比、路线、数量变化，而不是只能靠字幕讲。
4. 有反面：没有它会怎样、出错会怎样。
5. 不依赖写实画面（不需要真实照片或精确数据图也能讲清楚）。

结论：`fit`（适合）/ `reframe`（换个角度就适合，给 2 个具体角度）/ `reject`（不适合）。纯抽象概念（"黑洞的事件视界"）、纯数据、纯历史年表一般要 reframe。

## Stage 1 · 文案拆解

按 `project/script.clawd.template.md` 写 `script.md`，必须包含：

- 一句话核心；选题适配表。
- **世界设计**：视角（缩小进身体 / 剖面 / 鸟瞰 …）、主角长什么样以及状态怎么看出来、颜色语言、豆丁出现在哪几镜。
- **组件清单**：每个用到的组件一行，标明"复用"（写库里的名字）或"新建"（写清楚外观和参数）。新建组件通常 3–8 个，背景 2–4 种。
- **章节与旁白**：每句旁白一条，`[秒数] 旁白 ｜ 画面：背景 + 谁在哪里做什么 + 镜头`。旁白 ≤34 字、≤7.5 字/秒，每条 4–7 秒，全片 12–18 条（Stage 1.5 会把它们合并成视觉节拍）。
- **事实核对**：每条关键事实写清楚。

## Stage 1.5 · 视觉节拍

把已经定稿的文案翻译成**可拍的节拍表**。**不改文案、不重写旁白**：只决定每一句话观众看见什么。

**先定全局，再逐拍选**（顺序不能反）：
1. 先定 `cast`：谁是主角，要不要一个配角，谁来讲（`host`）。读完整篇后一次定好，之后不再改。
2. 再想整篇会用到几个地方（背景）：连续讲同一个地方的内容共用一个背景，换了地方才换。
3. 最后逐拍选 `background`、`subject`、`action`、`delta`、`change`。

每个 beat 写清楚：
- `background`：背景组件；`subject`：这一拍承担变化的**那一个**主体（组件名，或 `presenter`），同框的其它角色和道具写进 `action`，不要写 "A + B"。
- `action`：主体在做什么；`delta`：观众看见什么变化；`change`：变化类型。
- `sub`：字幕，≤34 字（口播路线里字幕由程序按单元填，不用写）。

规则：
- **每条旁白必须且只能属于一个 beat**。几句旁白可以并进同一个 beat（一个画面演几句话），但不能漏；抽象的句子不能单独成拍，要给它一个看得见的东西。
- `delta` 必须是**看得见的变化**：位置、缩放、颜色、数量、状态、表情、挂载、背景环境。标签出现和镜头推拉不算，它们只能强调。
- `change` 只能取：`move` / `scale` / `param` / `expression` / `appear` / `color` / `count` / `attach` / `environment`。
- **主体的选择**：主体是旁白此刻正在讲的那个东西：讲到主角就是主角，讲到配角就是配角，讲机制、环境或物件就是道具或前景（`subject` 不能留空）。**不需要每一镜都有角色**。`presenter`（豆丁）只用在引入、点题、收束的镜头。不要在两个角色之间逐拍轮换主体。
- 角色最多两个（主角 + 一个配角）。有脸的东西都算角色，都要登记在 `cast` 里；比喻里的东西做成道具，不给脸。
- 新组件写成 `{name, kind, face, purpose, tags}`：`tags` 是 3–5 个英文小写关键词，用组件库描述里的那类词（如 `bridge`、`canyon`、`night`、`interior`），写它是什么、什么场景、什么材质；之后按它去库里找候选，不要写中文，也不要照抄组件名。道具和背景 `face: false`，`purpose` 里不能出现脸、眼睛、表情、嘴；只有登记在 `cast` 里的角色才能 `face: true`。
- 组件名带类别前缀：背景 `bg_`、角色 `ch_`、道具 `pr_`、前景 `fg_`，并且 `kind` 与前缀一致。引用库里的组件时照抄库里的名字，不要写 `ch_critter:bean` 这种变体。
- 每个新组件都要出现在某个 beat 的 `subject`、`background`、`action` 或 `delta` 里（写组件名），否则删掉它。同一个东西在多拍里出现，只声明一次。
- 节拍表是 Stage 2 的**合同**：分镜只能补坐标、参数、镜头和额外道具，不能换主体、换背景或增删 beat。

## Stage 2 · 分镜 JSON

输出 `{"project": {...}, "storyboard": [...], "newComponents": [...]}`。

### project

```json
{ "title": "血液循环：跟着红细胞小红漂流一圈", "style": "clawd", "presenter": { "char": "bean" },
  "cast": { "protagonist": "ch_rbc_cell", "host": "bean", "characters": [{ "name": "小红", "component": "ch_rbc_cell" }] } }
```

`cast` 必填——**一期只跟一个主角**：
- `protagonist`：主角的组件；旁白讲到 ta 的镜头里出现 ta，不是每一镜都要有角色（讲机制、环境、物件的镜头可以没有角色）；同一个角色只用这一个组件（秋千上的人用 `pr_mv_swing` 的 rider，不另画）。
- `host`：`bean`（豆丁当主讲人）或 `protagonist`（主角自己发问、自己说答案，**所有镜头都不写 presenter**）。不能两个都上。
- `characters`：最多 2 个角色（主角 + 最多一个配角）。**有脸的东西都算角色**——比喻里的"化身"（"你就是那颗小球"）也算，会让观众以为换了主角；要演示的东西做成没有脸的道具。

### 坐标与构图

- 世界 1920×1080 像素，(0,0) 在左上。**字幕带盖住 y > 948**，重要的东西别放在那里。
- 非背景组件的 `x, y` 是**锚点 = 包围盒底边中点**（脚底）。组件的 `size` 写在索引里，例如 size [240,200] 的演员放在 y=650，就占据 y 450–650。
- 地面站位一般 y 820–900；主讲人默认 y 830，包围盒约 380×280（u=30）。
- 同一镜里按锚点 y 从小到大画（y 大的在前面）。要改前后顺序就给演员写 `depth`（只影响排序，例如荷叶 depth 700、站在上面的豆丁 y 805）。

### 挂点与地面（手持物必须贴手，别手调偏移）

- **`attach`**：`{"id": "b", "use": "balloon", "attach": {"to": "q", "at": "handL", "with"?: "grip", "dx"?: Track, "dy"?: Track}}`。`with` 是**挂载物自己**的某个锚点（杯子的 `grip`、雨伞的 `handle`）：不写就是挂载物的原点（底边中点）落在手上，写了就让这个锚点落在手上；拿在手里的东西几乎都要写 `with`。这个演员的位置 = 宿主 `q` 的某个挂点（`at`），随宿主移动、缩放、镜像、换表情和动作一起走；**写了 `attach` 就不要再写 `x` / `y`**（要微调用 `dx` / `dy`，单位是世界像素）。能挂的点就是宿主组件在组件库索引里列出的 **anchors**（角色有 `handL` `handR` `head` `chest`）。挂载物紧跟宿主之后绘制；`depth` / `layer` 可以另行指定。**手里拿的、头顶顶着的、胸前别着的东西都用它，不要用写死的 x/y 偏移去"跟着"角色**——角色一动、手臂一摆，偏移就会离手。挂载物组件的锚点就是被握住的那一点（气球的绳端、杯子的把手）。
- **`ground: true`**：演员站在背景的**地面线**上（背景在索引里标了 surface 才能用）：`y` 由背景算出，你写的 `y` 变成偏移，`x` 照常写。会晃的桥面、有坡度的地面都不用自己抄公式。
- `cam.follow` 和 `labels[].follow` 可以跟着挂载物。宿主必须是同一镜里的演员（不能是主讲人），不能互相挂成环。

### 动画值（Track）与切换值（Step）

- Track（数值，随时间变化）：
  - `5`：常量
  - `[0, 10]`：整镜从 0 缓动到 10
  - `[[0, 0], [1.5, 10]]`：关键帧（每段缓入缓出，**会在每个关键帧停一下**）
  - `{"through": [[0, -150], [2.2, 780], [4.8, 940], [7, 2100]], "ends": "linear"}`：途经点，准时经过、**途中不停**；`ends: "linear"` 时首尾也不减速（从画外冲进来、冲出去用它）。移动路线优先用这种。
- Step（任何值，到时间切换）：`"calm"` 或 `[[0, "calm"], [2, "surprised"]]`。
- 组件参数里：数值参数可以写 Track，其它参数写 Step。

### 视觉承载（每镜都要有变化）

- 每一镜至少有一处**演员 / 背景 / 前景的可见变化**：位置、缩放、朝向、组件参数、背景状态。
- **标签出现、镜头推拉不算**——它们只能强调，不能代替画面。只有标签或只有推拉的镜头，要么给主体加动作，要么并到相邻镜头。
- 静态画面只留给「想一想」这类刻意停顿，且不超过 4 秒。
- **节拍表的 `change` 必须写成会动的轨道，不能写成常量。** `shake: 0.9` 是「画成在摇的样子」，桥并不摇；`shake: [[0, 0.2], [3, 0.9]]` 才是摇。分镜的 `change` 与轨道对应关系：
  `environment` → 背景 params 有变化；`param` / `color` / `count` → 主体（或 delta 点名的道具）params 有变化；`move` → 主体 x/y 有变化；`scale` → 主体 scale 有变化；`appear` → 从 0 长出来；`attach` → `attach.dx/dy` 有变化；`expression` → 主体 params 或 `presenter.emotion` 有变化。
- 背景组件只能出现在 `background.use`，不能塞进 `actors` / `foreground`；要表现「另一个地方」，用道具或换背景。

### 镜头字段

| 字段 | 说明 |
|---|---|
| `id` `chapter` `dur` `sub` `read` | 必填。`dur` 1.5–12 秒；`sub` 字幕 ≤34 字且 ≤7.5 字/秒；`read` 一句话写观众此刻应该看懂什么（只写画面上真的会出现的东西） |
| `tin` / `tout` | 转场：`brush`（墨刷）/ `iris`（墨圈，圈心对准跟随的角色或主讲人）/ `drip`（滴落）/ `cut`。写在后一镜的 `tin` 上；第一镜的 `tin` 是片头，最后一镜的 `tout` 是片尾 |
| `background` | `{"use": "<背景组件>", "params": {...}}` |
| `actors` | `[{"id": "xh", "use": "<组件>", "x": Track, "y": Track, "scale"?: Track, "flip"?: Step, "depth"?: 数, "layer"?: "front", "params"?: {...}}]`，id 在本镜唯一。两种不写 x/y 的摆法见下面「挂点与地面」 |
| `foreground` | `[{"use": "<前景组件>", "x"?: Track, "y"?: Track, "params"?: {...}}]`，画在最上层 |
| `presenter` | 豆丁：`{"x": Track, "y"?: Track, "emotion"?: Step, "action"?: Step, "view"?: Step, "hat"?: "...", "tint"?: "none"\|"night"\|"warm", "u"?: 数, "depth"?: 数}`；不出场就省略或写 `null` |
| `cam` | `{"cx"?: Track, "cy"?: Track, "z"?: Track, "follow"?: "<演员 id>" \| "presenter"}`。`z` 1.0–1.6（1.6 = 推近），`follow` 让镜头跟着角色 |
| `labels` | 手写标签：`{"text": "红细胞", "follow"?: "<演员 id>"\|"presenter", "x"?: Track, "y"?: Track, "at"?: 秒, "until"?: 秒, "tint"?: "ink"\|"red"\|"blue"\|"green"\|"gold"\|"violet"}`。有 `follow` 时标签指向那个角色头顶、跟着走，`x/y` 变成偏移；没有 `follow` 时 `x/y` 是标签指向的点 |

主讲人取值：
- `emotion`：happy joy love shy sad cry angry surprised scared confused sleepy dizzy proud idea nervous bored gloomy excited smug hungry wink cool music calm
- `action`：none walk turn jump take dance smear（x 在变化时会自动走路）
- 朝向：不写 `flip` 时，走路朝走的方向，站着自动朝向画面中间（站在右半边就朝左）；要让它看向某个具体东西时再写 `flip`（true = 朝左）
- `view`：front q side qback back；`hat`：none party crown halo wizard top beanie bow flower headphones band hard leaf

**clawd 没有面板**（标题卡、公式、图表）：不要写 `panels`。要讲数字或对比，用标签、组件参数（例如进度、数量）或新建一个"图示"背景组件。

### newComponents（新建组件的契约）

```json
{
  "name": "bg_heart_pump",
  "kind": "background",
  "description": "Cross-section of the heart as a four-room pump: RA (640,390), RV (700,720), LA (1280,390), LV (1230,720) … (写清楚外观、颜色、关键部位在世界里的坐标，分镜要用这些坐标摆放别的东西)",
  "tags": ["bio", "heart"],
  "size": [1920, 1080],
  "params": {
    "highlight": { "type": "enum", "default": "none", "options": ["none", "ra", "rv", "la", "lv"], "description": "glow on one room" },
    "beat": { "type": "number", "default": 1.2, "min": 0, "max": 3, "description": "beats per second" }
  }
}
```

- `name` 用 snake_case，不能和库里重名；`kind`：background（size 必须 [1920,1080]）/ actor（角色）/ prop（道具）/ foreground（前景遮挡）。
- `size` 是包围盒，锚点在底边中点；角色一般 150–400 宽。
- **分镜里用到的每个参数都必须在 params 里声明**，类型一致，enum 的每个取值都在 options 里。
- `description` 要具体：长什么样、颜色、有没有脸、状态怎么变；背景要写出关键部位的坐标和"角色站在哪里"。
- 背景的 `tags`：身体里、微观、剖面、管道内部这类场景必须带 `interior`（主讲人不进这些场景）；关键部位的坐标写在 y ≤ 900（y > 948 被字幕带盖住）。
- 同一个角色只声明**一个**组件，不同形态用 enum 参数（如 `state`）区分，各形态主体大小一致，大小变化交给分镜的 `scale`。

## 视觉审查（印样）

印样每格是一个镜头 60% 处的画面。逐格检查：

1. 画面是否让观众看懂 `read`：主体是否明显、是否太小、是否和背景同色看不清、是否被别的东西挡住。
2. 标签是否压住主体、是否超出画面；有没有东西被字幕带（y > 948）挡住。
3. 是否几乎全空、只有背景。
4. 相邻镜头是否几乎一样。
5. 角色和背景是否"不搭"：组件是否真的像它代表的东西。

引擎能做的：背景/角色/道具组件和它们的参数动画、主讲人（表情、动作、朝向）、标签、镜头推拉跟随、三种转场。只报告严重影响理解的问题（最多 6 条），每条给出能用分镜字段实现的修改（挪位置、改 scale、改 depth、换 cam、改参数、改写 read）。

## 系列规划

复杂原理拆成**一个系列的多期短片**，每期 90–150 秒（12–18 镜），一期只回答一个问题。先选题适配，再一次写出**系列设定（bible）**和**大纲**。

选题适配在 Stage 0 五条之外再加两条（都必须满足才是 fit）：

6. 能拆成 3 个以上**有先后依赖**的子问题，每个子问题单独成立、2 分钟内讲得完。
7. 有一个能贯穿全系列的主比喻（或一组彼此兼容的比喻）。

系列设定（每期的文案和分镜都会带上，要具体、可画）：

- `world`：全系列共用的世界和视角；`presenter`：豆丁在系列里的身份（学徒、侦探、旅行者……），每期带着本期的问题出场。
- `colorLanguage`：颜色 → 含义，全系列不变。
- `masterMetaphor`：一句话主比喻。
- `metaphors`：比喻对照表，每条 `{concept, image, maps, breaksWhere, introducedIn}`。**`breaksWhere` 必填**：这个比喻在哪里不成立（防止观众学到错误类比），引入它的那期必须讲出来。
- `misconceptions`：常见误解 `{wrong, truth, episode}`，每期至少一条，给"豆丁先猜错"用。
- `protagonist`：**唯一的主角**（`characters` 里某个角色的组件）。观众从头到尾跟着 ta，每期大部分镜头都有 ta。
- `host`：主讲人二选一——`protagonist`（主角自己发问、自己试、自己说出答案，豆丁不出场）或 `bean`（豆丁当主讲人）。**不能两个都上**。
- `characters`：贯穿全系列的角色 `{name, component, role}`，**最多 2 个**（主角 + 最多一个配角）。`component` 是库里的名字、`ch_critter:<char>`（库里的小动物，如 `ch_critter:mian`）或 `components.new` 里的名字。一个角色只用一个组件；要演示的东西（钟、罐子、小妖……）做成道具，不要做成角色。
- `components`：`{reuse: [库组件名], new: [{name, look, params}]}`。新组件由第一次用到它的那期画出，之后各期直接复用。

大纲每期一条：`{n, title, goal, question, metaphors: [concept], misconception, dependsOn: [前面的期号], cliffhanger}`。`question` 要具体、能想象（"一个小工人怎么决定要不要往下传？"，而不是"什么是神经元"）；`cliffhanger` 是留给下一期的问题，最后一期留空。

## 系列期文案（苏格拉底式）

系列里的每一期按节拍写。**章节与旁白里每一镜的画面说明前标一个节拍标记**，例如 `[5] 旁白 ｜ 【猜】画面：……`：

| 节拍 | 标记 | 镜数 | 写什么 |
|---|---|---|---|
| 回顾 | 【回顾】 | 0–1 | 第 2 期起必有：上一期留下的问题 |
| 提问 | 【问】 | 1 | 本期核心问题（大纲的 question） |
| 猜错 | 【猜】 | 1–2 | 豆丁按本期的常见误解作答，画面演出它的猜法 |
| 反例 | 【反例】 | 1–3 | 一个小实验或反例推翻猜测 |
| 追问 | 【追问】 | 0–2 | 把问题缩小到关键处 |
| 想一想 | 【想】 | 0–1 | 问题停在画面上：字幕只写问题，3–4 秒，画面基本静止 |
| 揭示 | 【揭示】 | 2–5 | 用比喻演出答案；本期引入的比喻在这里出场 |
| 失效 | 【失效】 | 每个新比喻 1 | 这个比喻在哪里不成立 |
| 回扣 | 【回扣】 | 1 | 回到开头的问题，一句话答案 |
| 悬念 | 【悬念】 | 0–1 | 下一期的问题（最后一期没有） |

顺序：回顾 → 问 → 猜 → 反例 →（追问 / 想）→ 揭示 → 失效 → 回扣 → 悬念。**不能先讲答案再提问**；揭示之前必须有反例。前几期已经引入的比喻再出现时，用同一个组件、同一个说法。
